Overview

Closing the Linux gap

Minecraft Education Edition ships for Windows, macOS, ChromeOS, and Android — but not Linux. This project closes that gap with one portable AppImage that:

  1. 1

    Sets up Waydroid — Android in a container — automatically on first run.

  2. 2

    Installs the official Minecraft Education Android app (split APK bundle) into it.

  3. 3

    Launches the game in its own window on your Linux desktop.

The entire Android environment lives inside the app's own data directory, so your host system stays clean — uninstalling is a single command. No Google account, no Play Store registration, no manual Waydroid configuration.

Features

Everything handled for you

Designed around isolation, idempotency, and instant relaunch.

📦

Single-file distribution

One ~200 KB AppImage. The Android image (~2 GB) and game package (~413 MB) are fetched on first run only.

🔒

Fully isolated

All Android data lives under ~/.local/share/mc-education; /var/lib/waydroid is redirected there via symlink.

🚫

No Google account required

Installed with adb install-multiple — the same mechanism the Play Store uses — straight from the APK bundle.

🪟

Windowed or fullscreen

Defaults to a dedicated game window; --fullscreen switches to the full Android UI.

⚡

Fast relaunch

A healthy Android session is reused instead of rebooted: repeat launches complete in ~1 second.

🩹

Self-healing cleanup

Every launch validates the session and cleans up stale containers, dead-session tracking, and leftover processes before booting.

🔑

Robust adb integration

Host-side key provisioning (Android's proprietary key format via adb keygen) — no root access for install or launch.

🩺

Diagnostics built in

--check performs a full environment audit; detailed logs are written to ~/.local/share/mc-education/logs/.

🔁

Idempotent setup

All system-level steps are safe to re-run; setup never repeats completed work.

Architecture

How the pieces fit together

Everything the user touches runs inside one portable AppImage.

AppImage portable · ~200 KB
AppRun → mc-education (orchestrator, runs as the user)
download_apk APKPure · ~413 MB · split APKs
prepare_adb_key adb keygen → host-side key write
start_session reuse healthy · or cold boot via setsid
↓
Waydroid session Android 13 / LineageOS 20
adb install-multiple 5 APK parts · as user
waydroid app launch creates the visible window
↓
One-time setup first run only

A single admin prompt (pkexec/sudo) runs: binder module · Waydroid apt install · waydroid init -s GAPPS (~2 GB) · waydroid-container service.

Why it's designed this way

  • adb for install, platform service for launch. The game is installed over adb (install-multiple handles split APKs natively) but launched with waydroid app launch, which routes through Waydroid's platform service — the only path that creates a visible window on the host desktop. A raw adb am start produces no window and is deliberately avoided.
  • Key provisioning before boot. Android's adbd reads /data/misc/adb/adb_keys exactly once, at boot, and only accepts Android's proprietary pubkey format. The launcher generates the key with adb keygen and writes it host-side before the session starts — no root, no restart race.
  • Native x86_64 Android image. No ARM translation layer is needed, so the game runs at full speed.

Quick Start

Up and running in two commands

Terminal
# Build it
./build-appimage.sh

# Run it (or double-click the AppImage in your file manager)
./Minecraft-Education-Linux-x86_64.AppImage

That's it. The first launch performs one-time setup; every launch after that is automatic.

What happens on first run?

  1. Downloads the game package (~413 MB) from APKPure and extracts the 5 APK parts.
  2. Asks for your admin password once (graphical pkexec dialog; --sudo for terminals) and runs one-time setup: binder module · Waydroid install · Android image with GApps (~2 GB) · enables the waydroid-container service.
  3. Boots the Android session and waits until Android reports fully booted.
  4. Installs Minecraft Education via adb install-multiple — no Google account, no further password prompts.
  5. Launches the game in its own window.

Sign in inside the app with your Microsoft 365 Education account as usual.

💡 First launch takes ~5–10 minutes

That's the one-time download and setup. Every launch after that takes about a second — a healthy Android session is reused instead of rebooted.

Total first-run download: ~2.4 GB (Android image + game package).

Usage

Command-line reference

One binary, a handful of useful flags.

Terminal
./Minecraft-Education-Linux-x86_64.AppImage [options]
FlagDescription
(no flags)Install (if needed) and launch the game.
--help, -hShow the built-in help.
--checkAudit the environment (OS, Wayland, binder module, Waydroid, images, disk space) without changing anything.
--repairRe-download the game package and reinstall it into Android.
--fullscreenRun inside the fullscreen Android UI instead of a dedicated window.
--resetDelete all app data (~/.local/share/mc-education) and exit.
--sudoUse sudo instead of pkexec for the admin step (e.g. terminal-only environments).
--force-x11Skip the Wayland check (Waydroid requires Wayland; only use with Weston).

To fully shut down the background Android session after playing:

waydroid session stop

Session lifecycle

Launch speed is handled by a health check + reuse strategy.

launch
Is Android already running and answering over adb?
yesReuse the session~1 second
no
Stop stale session / container (if any) Boot a fresh session ~10–15 s warm · minutes on first ever boot

Why relaunch is instant

  • The session starts with setsid, so it keeps running in the background after the launcher exits — the next launch finds and reuses it.
  • A session is healthy only if Waydroid reports RUNNING and Android answers sys.boot_completed=1 over adb. Anything less triggers the clean-boot path.
  • Android's screen-off is disabled after install, so the container never suspends or freezes.
  • The background session consumes RAM until you stop it (waydroid session stop) or reboot — the deliberate trade-off for instant relaunch.

Data isolation

Your system stays clean

Everything the app owns lives in one directory.

PathContents
~/.local/share/mc-education/apk/Downloaded package + extracted APK parts + install state markers
~/.local/share/mc-education/waydroid/Android image, user data, installed apps
~/.local/share/mc-education/adbkey*adb keypair (Android format) used for installs
~/.local/share/mc-education/logs/setup.log, session.log, install.log

/var/lib/waydroid is a symlink into ~/.local/share/mc-education/waydroid/ — deleting that one folder removes everything Waydroid owns.

Uninstall (complete)

Terminal
./Minecraft-Education-Linux-x86_64.AppImage --reset    # removes all app data
rm Minecraft-Education-Linux-x86_64.AppImage            # removes the launcher

The only system-level changes — all made by the one-time root setup, all reversible:

  • binder_linux kernel module auto-load → remove /etc/modules-load.d/waydroid.conf if desired
  • waydroid apt package + repo.waydro.id source → sudo apt remove waydroid
  • waydroid-container systemd service → sudo systemctl disable --now waydroid-container

Security

Least privilege, by design

🔑 Least privilege

The launcher runs entirely as the normal user. Root is invoked only for one-time system setup and emergency cleanup — never for install, launch, or adb.

🗝️ adb key handling

A dedicated keypair generated with adb keygen lives in the app's private data dir — never your personal ~/.android. The container sees only the public half (mode 0640, group shell).

🙅 No Google account data

Install happens via adb from the downloaded APK bundle — no Play Store login, no GSF registration on your host.

🌐 Network surface

Downloads come from APKPure (game), repo.waydro.id / SourceForge (Waydroid + image) only. In-game sign-in talks to Microsoft's official services, as on any platform.

📦 Isolation

Android runs in an LXC container confined to your home directory; removing it removes the entire Android environment.

🧾 Auditability

Every setup step logs to ~/.local/share/mc-education/logs/; --check reports exact environment state at any time.

FAQ

Frequently asked questions

Do I need a Google account?

No. The game is installed from the APK bundle over adb, without touching Google Play.

Does Minecraft Education run natively?

The Android build ships x86_64 binaries, so there is no ARM translation overhead. Performance depends on your GPU/Wayland compositor; fullscreen mode generally performs best.

Where is the game downloaded from?

APKPure, a third-party mirror of the free Play Store app. In-game sign-in still uses your official Microsoft Education account.

Does this touch my personal adb keys?

No. The launcher generates a dedicated keypair inside ~/.local/share/mc-education/ and registers it for the Waydroid session only.

Why does the app need admin rights at all?

Exactly three one-time operations require root: loading a kernel module (binder_linux), installing the Waydroid apt package, and enabling its systemd service. Everything else — install, launch, updates — runs as your user.

How do I update the game?

Minecraft Education updates itself inside Android. To force a clean reinstall: ./Minecraft-Education-Linux-x86_64.AppImage --repair.

Can I move the AppImage around?

Yes — it is fully portable. App data stays in ~/.local/share/mc-education, independent of where the AppImage file lives.

Troubleshooting

When something goes wrong

Logs for every component live in ~/.local/share/mc-education/logs/. When in doubt, run the AppImage from a terminal and read the output.

Nothing happens when double-clicking

Run from a terminal to see output: ./Minecraft-Education-Linux-x86_64.AppImage. Check the logs under ~/.local/share/mc-education/logs/.

“No Wayland session detected”

You're on X11. Waydroid requires Wayland — start Weston and launch the AppImage from inside it, or pass --force-x11 at your own risk.

“failed to load the binder_linux module”

Your kernel lacks the Android binder driver. Run --check to confirm. Stock Ubuntu/Debian kernels include it; custom or older kernels may not.

Game runs but no window appears

Ensure you're launching with the current build. waydroid app launch (used by the launcher) creates the window; a raw adb am start does not. If the window still doesn't appear, check your compositor/taskbar and the session log.

“adb: device unauthorized”

adbd only accepts keys in Android's proprietary pubkey format (adb keygen, not ssh-keygen), and it reads them once at boot. The launcher handles both. If it ever happens anyway: delete ~/.local/share/mc-education/adbkey* and re-run — the key is re-provisioned before the next boot.

“Couldn't get LXC status. Assuming STOPPED” in waydroid.log

A known Waydroid quirk on some kernels: after Android suspends (~70 s idle) the container is frozen and lxc-info fails to report state — making Waydroid believe the container is STOPPED while it is actually healthy. The launcher prevents the freeze outright by disabling Android's screen-off, and never relies on lxc-info for the install path (it uses adb).

“RuntimeError: Already tracking a session”

A previous session died uncleanly but the container service still tracks it. The launcher detects and clears this by restarting the container service and killing any leftover container directly (lxc-stop -k).

Slow launches (>1 min)

This is the cold-boot path (no healthy session exists). Repeat launches should reuse the session in ~1 s. If every launch cold-boots, the session is dying between launches — check session.log.

On-screen keyboard pops up

Inside Android (Waydroid shell → Settings → System → Languages & input → Physical keyboard), disable “Use on-screen keyboard”.

Sign-in problems in-game

Minecraft Education requires a valid Microsoft 365 Education account.

Sluggish gameplay

Games run best in fullscreen: ./Minecraft-Education-Linux-x86_64.AppImage --fullscreen.

Still stuck? Get help fast

Open a GitHub issue and attach the relevant log from ~/.local/share/mc-education/logs/ plus the output of ./Minecraft-Education-Linux-x86_64.AppImage --check. The --check flag plus the three log files cover ~all failure modes.

Build from source

Terminal
./build-appimage.sh

Needs only curl and python3. The game package and Android image are fetched at runtime, on first launch. If the output file is still mounted (an instance running), the build fails with “Text file busy” — close any running instance first.

Contributing

Keep changes consistent with the existing design:

  • Isolation first — everything user-facing stays under ~/.local/share/mc-education; no new global state without strong justification.
  • No new root paths — prefer user-space mechanisms (adb, host-side key writes) over escalated ones.
  • Session reuse stays — healthy sessions should be reused, not rebooted.
  • Verify end-to-end — test the full flow: fresh setup → install → launch → relaunch (reuse path).
Before submitting
# syntax check
bash -n src/mc-education src/waydroid-setup.sh src/AppRun
